# dotの作業報告（#609）

dotが**明示的に報告した利用者向けの節目**をAIDEで受け取り、保存し、読み戻せるようにする。
全活動の自動収集は対象外。MCPアクセス履歴（`data/mcp-access.json`）から作業状況は復元できず、
通知（`aide_create_notification`）や正式タスク/タスク候補の登録でも代用しない。
親Issue: guchi-apps/status-hub#574。

## 公開するもの

| 経路 | 用途 | 認可 |
|---|---|---|
| MCP `aide_report_work` | 作業の節目を報告する（書き込み。承認単位は**1回の報告**） | OAuth scope `work-reports:write` |
| MCP `aide_work_reports` | 保存済みの作業を読み戻す | OAuth scope `work-reports:read` |
| `GET /api/work-reports` | StatusHubが同じ正本を読む | `AIDE_WORK_REPORTS_READ_SECRET`（`AIDE_READ_SECRET`・`AIDE_STATUS_SECRET` とは別の値） |

読み取りと書き込みは別ツール・別scope（既存の方針。クライアントで読み取りを「常に許可」にしても書き込みは素通しにならない）。
既存ツールのscopeは変えない。

## 契約（`aide_report_work`）

| 項目 | 必須 | 内容 |
|---|---|---|
| `workId` | ○ | 作業を表す安定したID。英数字と `. _ : -`、100文字以内 |
| `eventId` | ○ | 報告1回ごとのID。同じ条件の形式。**再送のときだけ同じ値を使う** |
| `version` | ○ | 作業ごとの更新版。1以上1,000,000以下の整数 |
| `status` | ○ | `started`（開始）/ `running`（実行中）/ `waiting`（待機）/ `completed`（完了）/ `failed`（失敗）/ `cancelled`（取消） |
| `occurredAt` | ○ | 発生時刻。タイムゾーン付きISO 8601。5分を超える未来は拒否 |
| `title` | 最初の報告のみ○ | 作業名。80文字以内の1行。省略すると前の値を保つ |
| `progress` | | 短い進捗。200文字以内の1行。省略すると空になる |
| `waitReason` | | 待機理由。`waiting` のときだけ。200文字以内 |
| `resultSummary` | | 結果要約。完了・失敗・取消のときだけ。400文字以内 |
| `links` | | 関連リンク。5件まで・各300文字以内 |

サーバーが付与する値: **受信時刻（`receivedAt`）・所有者・報告元（`reporter`）**。**これらは引数で受け取らず**
（受け取らない項目を渡すとエラー）、自己申告も信頼しない。

- **所有者**: AIDEは単一利用者前提のため固定。OAuthで認可された本人の接続だけが読み書きできる（未認可・scope不足は拒否）。
- **報告元**: 認可済みアクセストークンに結び付いたOAuthクライアントID。再接続（クライアント登録のやり直し）で変わりうるため、所有者の判定には使わず記録だけにする。クライアントの表示名は保存しない。
- 許可した項目以外・文字列の改行や制御文字・認証情報らしい文字列（Bearer/JWT/APIキー/秘密鍵/長い16進など）は**保存せず拒否**する。会話やメールの原文を送らないこと。
- **リンク**: `https` のみ。ユーザー情報・クエリ・フラグメント付き、`localhost`・IP直指定・内部向けホストは拒否（署名付きURL・トークン入りURLを丸ごと対象外にする）。

## 状態遷移と更新の順序規則

| 状況 | 結果 |
|---|---|
| 新しい版（現在より大きい） | `applied`。保存して適用版を返す |
| 同じ `eventId`・同じ内容 | `duplicate`。書き直さず保存済みの状態を返す（`saved:true`） |
| 同じ `eventId`・内容が違う | **競合**（`kind: conflict`、エラー） |
| 別 `eventId`・現在と同じ版 | **競合**（同一版の競合） |
| 現在より小さい版 | `stale`。**適用しない**（`saved:false`。最新状態を巻き戻さない） |
| 終了（完了・失敗・取消）後の新しい版 | 拒否（`kind: invalid_transition`）。新しい `workId` で報告する |
| 途中の報告に `started` | 拒否。開始は最初の報告にだけ使える |

`running`↔`waiting` は自由に行き来できる。最初の報告はどの状態でもよい（`started` の報告が失われても続けられる）。
内容は報告ごとに丸ごと置き換わる（`title` だけ省略時に前の値を保つ）。

## 安全な再送

応答に `saved: true` が無いものは保存済みと扱わない（受付だけを成功としない）。
応答を失ったら、**同じ `eventId`・同じ内容で再送**するか、`aide_work_reports`（`workId` 指定）で読み戻す。
`saved:true`・`result:duplicate` が返れば、二重登録されていない。保存に失敗したときは `kind: storage_error`（`saved:false`）。

## 保存

- `data/work-reports.json`（`.gitignore` 済み。`AIDE_WORK_REPORTS_PATH` で差し替え可）。一時ファイル→`rename` の原子的書換えで、書込みはプロセス内で直列化する。**`saved:true` は `rename` が終わった後だけ返す**。
- 再起動・再デプロイ後も残る（`data/` はデプロイで消さない）。
- **壊れたファイルは上書きしない。** JSONとして読めない・形が不正なときは、書込みも読取も失敗する（人が調べて直す）。他の冪等記録（`core/record-file.ts`）の「壊れたら空として扱う」は使わない。
- 保持: **作業は最終受信から90日・最大200件**（超えたら終了済みの古いものから捨てる）。**作業ごとの重複判定用イベントIDは直近50件**（それより古い eventId の再送は重複として検知できない）。
- 一覧の取得: 既定20件・**上限50件**。受信時刻の新しい順。
- 保存するのは許可項目だけ。ログへは報告の本文を出さない（エラーにも含めない）。イベントの内容そのものは持たず、同一性判定用のハッシュだけを持つ。

## 鮮度と「何が起きていないか」の区別

読み取りの応答（MCP・REST共通）:

| 状態 | 見え方 |
|---|---|
| 無報告 | `200` / `reportState: "none"`・`works: []` |
| 報告あり | `reportState: "reported"`。作業ごとに `freshness` |
| 更新途絶 | 進行中の作業を、最終受信から30分超で `freshness: "stale"`（`staleCount` で件数） |
| 終了 | `freshness: "final"`（完了・失敗・取消） |
| 取得失敗 | REST は `503`、MCP は `isError`（`kind: read_failed`）。**空の一覧（200）とは別** |

**更新途絶（`stale`）から完了・失敗を推定しない。** `status` は報告された値のまま返す。

## 既存MCP方針との整合

- 1ツール1つの問い、読み書きは別ツール・別scope（#373）。
- 書込みは明示依頼があったときだけ呼ぶ前提で、説明文に「利用者向けの節目だけ・原文や認証情報は送らない」と書く。
- ツールの引数は `additionalProperties: false`。サーバー側でも許可項目だけを検証する。
